# Wi-Fi 中继（v0.1.2-experimental）

这是国行 B28 原厂驱动上的扩展，不是通用 OpenWrt 中继设置。本页行为自 v0.1.2-experimental 安装包提供，旧 v0.1.1 安装包不包含这些改动。

## 使用

1. 开启 5G 主热点、关闭访客热点，将 USB 网口设为 LAN。2.4G 主热点可以保留开启，也可在中继期间单独开关。
2. 屏幕进入“网络 → Wi-Fi → 连接 / 更换上游 Wi-Fi”；原厂网页进入“增强功能 → 网络”的同名入口。
3. 扫描结果按 2.4G、5G 分开，同名同频段、相同加密方式的重复接入点保留较强信号。选择网络，在自己的设备界面输入密码；不必先手动断开现有中继。
4. 连接后显示实际“2.4G 上游中继”或“5G 上游中继”。仅连接一个上游，不叠加两条 Wi-Fi 带宽。

凭据保存在 U60 本机权限受限的配置文件中。自动重连保持所选频段，可在该频段内选择兼容的同名接入点；不会默认跨到另一频段。保存重连意图不等于已完成所有冷启动场景验收。

同频热点要与上游协调信道。由于 B28 的在线 CSA 曾出现驱动未完成切换但管理程序报成功，本版先停用对应热点 BSS，修改其运行时信道后再启用，并核对驱动和管理程序报告是否一致。对应频段客户端会短暂断开重连。原厂持久 Wi-Fi 设置不重写；退出中继尝试恢复原运行时信道和带宽。

## 流量与冲突

热点和手动 LAN 下属设备共用当前上游；已有 Clash IPv4 TCP/DNS 分流及 Tailscale 子网配置继续工作。路由状态、真实下属请求和实际出口流量增量须一起验收，不能只看页面显示“已连接”。

- **断线可自动回退蜂窝并消耗 SIM 流量**；这不是蜂窝断流保护功能。
- 中继期间互联网 IPv6 沿用阻断默认出口的策略；不宣称任意 IPv6/UDP 代理或全面防泄漏。
- 当前要求 USB LAN、访客热点关闭和 5G 主热点开启。与原厂休眠、热点关闭或 USB 冲突时释放自建 STA，条件恢复后尝试重连。
- 2.4G 支持信道 1–13；5G 支持非 DFS 的 36/40/44/48、149/153/157/161/165。DFS 不在列表中；160MHz、地区差异与拥塞组合未全面验证。
- 只处理有兼容上游和可用租约的情况。上游仍有 Wi-Fi 但互联网已断的主动探测尚未完成。

## 本次证据与未验证范围

一台国行 B28 上：修复后的 2.4G 上游下，用户分别连接自身两个热点，百度、Google 都正常。5G 上游有设备及 USB 下属自动业务测试，但修复后的完整手机双热点验收尚未完成。相关测试期间中继接口产生流量、蜂窝收发增量为零，只代表这些测试时段，不是永不消耗蜂窝的保证。

Tailscale 在线节点与下属到 Tailnet 的自动通信通过；此前外部手机到子设备的人工验收有记录，但新修复没有再次完成外部手机全链路验收。真实长休眠、冷启动、长期负载/功耗、全部上游加密组合、第二台新设备首装仍未验证。

本版还修复了首页标题周期性闪为运营商的问题：慢速后台快照不再覆盖本地实时出口。实际路由回退仍会显示，未通过隐藏蜂窝状态来消除闪动。

出现异常时先用 UI 关闭中继，确认两热点与原出口恢复。排查时优先 USB ADB，保留密码、订阅、Tailscale 身份和原厂设置；不要反复重启整机或删除配置。已有安装没有通用无损升级命令，不能用首装脚本强制覆盖。
